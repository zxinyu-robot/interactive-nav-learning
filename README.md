# Interruptible Interactive Navigation Learning

**我们提出了一种可中断交互式导航学习框架。**

该框架允许人类在机器人自主导航过程中随时接管控制，并根据环境变化、任务歧义、导航风险或策略失效进行实时干预。系统将人类介入视为一种重要的交互式反馈信号，关联记录介入时的环境状态、任务意图、机器人原有行为与人工修正动作，从而分析自主策略与人类决策之间的差异。

在此基础上，框架探索将人类的纠正行为转化为可积累、可检索和可复用的导航经验，使机器人能够逐步学习不同场景下的行为选择与任务执行策略。当人工接管结束后，机器人根据定位与环境状态的可信度、路径可行性及安全约束，判断是否具备恢复自主执行的条件，并在必要时继续请求人工介入。

框架的核心目标是建立一个**人类监督、机器人自主执行、经验持续积累**的协同闭环：既保留传统导航系统在状态估计、路径规划和运动控制方面的可靠性，也为机器人从人类反馈中学习情境相关的行为策略提供接口。学习模块负责策略改进与经验积累，底层安全机制负责执行约束与风险处理，避免将未经验证的学习结果直接转化为运动指令。

## Quickstart

**环境要求：** Python 3.11+

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# 1. 生成初始教师示范数据
# A* 仅作为教师，用于生成训练示范
interrupt-nav generate --config configs/smoke.json \
  --episodes 2 --output artifacts/smoke.jsonl

# 2. 行为克隆（Behavior Cloning）
interrupt-nav train --config configs/smoke.json \
  --data artifacts/smoke.jsonl --output checkpoints/bc.pt

# 3. 评测学习策略
# 评测 rollout 不调用 A* 或其他路径规划器
interrupt-nav evaluate --config configs/smoke.json \
  --checkpoint checkpoints/bc.pt --output artifacts/report.json

# 4. DAgger 风格的数据聚合与迭代训练
# 教师可以为策略访问到的新状态提供监督标签
# 教师查询仅发生在数据采集/标注阶段
interrupt-nav dagger --config configs/smoke.json \
  --checkpoint checkpoints/bc.pt --data artifacts/smoke.jsonl \
  --output-data artifacts/dagger.jsonl \
  --output-checkpoint checkpoints/dagger.pt

# 5. 演示学习策略在执行过程中的目标纠正
interrupt-nav demo --checkpoint checkpoints/dagger.pt --steps 40

# 6. 最小端到端示例
python examples/minimal.py
```

`smoke` 配置用于验证代码链路，不代表充分的模型评测。正式实验应增加 episode 数量、使用多个随机种子，并对不同策略进行相同条件下的对比。

在固定配置、随机种子、软件版本和执行环境的条件下，项目尽可能保证环境采样与训练流程的可重复性。不同 PyTorch、BLAS、操作系统或硬件环境之间不保证浮点计算结果逐位一致。

## 项目目标与当前实现边界

我们研究一种**可中断、可纠正、可持续积累经验的交互式导航学习框架**。

机器人在执行导航任务时，可以接收目标变更、区域约束、方向约束和暂停/恢复等纠正信号。系统将这些信号与当前观测、动作和任务上下文关联起来，用于训练能够响应交互反馈的导航策略。

项目希望验证三个核心问题：

1. **纠正响应：** 学习策略能否及时响应目标变化和行为约束，而不是继续执行过时的导航意图？
2. **经验积累：** 通过行为克隆与 DAgger 风格的数据聚合，能否改善学习策略在自身访问状态分布上的表现？
3. **自主执行：** 在不依赖在线路径规划器的情况下，学习策略能否完成导航任务，并在纠正发生后恢复适当的行为？

需要明确的是：当前版本是一个轻量级研究原型。DAgger 中的教师由 A* 等规则化规划机制模拟；这不等同于已经实现真实的人类实时接管、遥操作接口或真实机器人上的安全控制。因此，当前结果主要用于验证可中断交互和纠正学习机制，而不是证明完整的人机协作系统已经落地。

### 训练与推理的数据流

```text
教师示范生成
    A* 教师
       |
       v
  初始示范数据
       |
       v
 行为克隆（BC）
       |
       v
  初始学习策略
       |
       v
策略 rollout 与状态采集
       |
       +----> 教师查询 / 纠正信号
       |                 |
       +--------+--------+
                v
          数据聚合
                |
                v
          迭代再训练
                |
                v
           学习策略
                |
                v
        无规划器策略推理
                |
                v
       执行约束与环境反馈
```

教师规划器用于产生监督信息，而不是部署策略的一部分。学习策略直接根据当前观测与历史交互信息输出动作；环境中的硬约束机制负责执行必要的禁区、方向和暂停限制。

**必须区分策略能力与约束机制的能力。** 如果环境直接阻止某个动作被执行，机器人最终没有违反约束，并不能单独证明学习策略已经理解或学会了该约束。

### 策略输入

当前设计中的观测特征包括：

- **距离观测：** 归一化到 `[0, 1]` 的距离射线，用于描述局部障碍与可通行空间。
- **运动状态：** 当前线速度、角速度以及机器人朝向。
- **目标状态：** 相对目标距离与方位。
- **任务语义：** 固定、版本化的语言目标 token。
- **交互上下文：** 最近的纠正 token，以及当前仍然生效的约束信息。

GRU 用于保留跨时间步的隐状态，使策略能够利用短期历史信息，而不是将每一步决策都视为独立的静态映射。

对于持续有效的禁区与方向限制，单独保留最近一个纠正 token 并不足够：多个约束可能同时生效。因此，建议将当前有效约束集合显式编码到观测中，或提供等价的可查询状态接口，避免新纠正覆盖掉尚未解除的旧约束。

### 策略输出

模型输出包括：

- 受限线速度；
- 受限角速度；
- 独立的 `stop` 二分类头；
- 独立的 `ask` 二分类头。

`stop` 表示策略请求停止运动，`ask` 表示策略请求人工协助。两者不能混为一谈：停止运动不一定意味着需要人工介入，而发出 `ask` 也不代表人工控制器已经连接或成功接管。

在线推理不由 LLM 直接生成速度指令。速度输出由已训练策略产生，并经过动作边界及执行约束处理。

## 中途纠正机制

当前支持以下纠正类型：

| 纠正类型 | 语义 | 需要验证的学习行为 |
|---|---|---|
| `change_goal` | 立即替换当前导航目标 | 策略能否转向新目标，而非继续追逐旧目标 |
| `forbid_region` | 将指定矩形加入动态禁区 | 策略能否调整后续运动，绕开受限区域 |
| `forbid_direction` | 禁止 `left`、`right` 或 `forward` | 策略能否停止选择与限制冲突的动作 |
| `stop` | 暂停当前任务 | 策略能否停止运动，并维持暂停状态 |
| `continue` | 恢复已暂停的任务 | 策略能否在当前目标与约束仍然有效的条件下恢复执行 |

当前版本应明确约束的生命周期：禁区与方向限制在本 episode 内持续有效，除非已有显式机制将其解除。若后续需要支持临时禁区、约束撤销或用户更正之前的限制，应增加对应的解除事件，而不是依赖隐式覆盖。

环境会强制执行已实现的禁区、方向和暂停约束。该机制提供的是原型环境中的执行约束，不构成形式化安全证明，也不能直接推导出真实机器人中的碰撞避免保证。

### 纠正响应与安全执行必须分别评估

纠正发生后，系统应分别记录：

1. 学习策略在约束处理之前输出了什么动作；
2. 环境或执行约束层最终允许执行什么动作；
3. 最终执行是否符合安全约束；
4. 策略是否在规定的响应窗口内表现出符合纠正意图的行为。

例如，`forbid_direction` 生效后，环境可能直接拦截策略输出的违规动作。此时实际执行动作虽然安全，但原始策略可能仍在反复输出违规动作。

因此，**不能仅根据最终执行动作计算学习策略的纠正响应时间**。如果当前 `StepRecord` 只保存实际执行动作，而没有保存约束处理前的策略输出，就需要扩展数据 schema；否则，这一指标无法可靠地区分策略学习与环境拦截的贡献。

## 数据格式

数据以 JSONL 作为存储格式，每行对应一个完整的 `Trajectory`，包含版本信息、一个 `Episode` 和有序的 `StepRecord`。

核心对象由 dataclass 实现，并通过 `read_jsonl` 与 `write_jsonl` 进行读写和往返序列化测试。

示例：

```json
{
  "version": "1.0",
  "episode": {
    "episode_id": "seed-0",
    "seed": 0,
    "start": [1, 1, 0],
    "goal": [5, 5],
    "obstacles": [],
    "max_steps": 30,
    "language": "go to the goal",
    "corrections": [],
    "shortest_path": 5.66,
    "version": "1.0"
  },
  "steps": []
}
```

其中，`episode.corrections` 用于表达预先指定的纠正事件（如果有）；`step` 中的纠正记录则用于保存交互执行过程中实际发生的事件。两者应有明确的数据语义，避免同一纠正事件在回放、训练和评测中被重复计算。

每个 step 应记录观测、动作、可选教师动作、纠正事件、奖励、终止标志和干预标志。建议进一步将以下三个概念分别存储：

- `policy_action`：学习策略未经执行约束处理的原始输出；
- `executed_action`：经过环境约束处理后实际执行的动作；
- `teacher_action`：教师针对当前观测提供的监督动作。

如果现有 schema 暂时尚未区分这些字段，应在代码和文档中明确现有 `action` 的具体含义，并在计算学习效果指标前完成必要的数据扩展。

在 DAgger 数据聚合过程中，教师查询必须针对学习策略实际访问到的状态；若当前目标或有效约束发生变化，教师标签也必须与当前任务语义保持一致。否则，初始目标下生成的教师动作可能与后续人工纠正相冲突。

## 评测定义

所有评测均以机器可读 JSON 输出，并包含逐 episode 明细。总体汇总应保留每个 episode 的原始结果，避免只报告单个平均值而掩盖失败案例。

| 指标 | 定义与注意事项 |
|---|---|
| `success` | 在给定 horizon 内完成当前任务的 episode 比例 |
| `spl` | 成功指示 × 参考最短路径长度 / max(参考最短路径长度, 实际行驶路程) |
| `collisions_per_100m` | 碰撞次数 / 实际行驶距离 × 100 米 |
| `interventions_per_episode` | 每个 episode 中教师接管执行的次数；如统计的是纠正事件，应另行命名 |
| `correction_response_steps` | 从纠正发出到原始策略输出满足对应响应判据的时间步数 |
| `control_smoothness` | 相邻归一化控制量变化的均值，数值越低表示控制变化越平缓 |
| `ask_rate` | 输出 `ask` 的时间步数占比 |

### 指标计算约定

**Success 与目标纠正：** 如果 episode 中途发生 `change_goal`，成功判定应以当前有效任务目标为准，不能继续沿用已经作废的初始目标。

**SPL 与目标纠正：** 参考最短路径必须对应同一任务协议。如果目标发生变化，应按相同的目标变化序列计算参考路径长度；若暂时无法做到，就只在目标未发生变化的 episode 上报告 SPL，并明确统计范围。

**纠正响应时间：** 每种纠正应有独立、可测试的响应判据。例如：

- `stop`：策略原始输出达到预设的零速度或低速度判据；
- `change_goal`：策略行为满足朝向新目标推进的判据；
- `forbid_direction`：策略原始动作不再违反方向限制；
- `forbid_region`：策略后续行为满足避开禁区的判据。

未在 episode 结束前响应的纠正按剩余 horizon 计入延迟，避免静默忽略失败。响应判据应避免将“环境拦截了违规动作”误判为“策略已经学会纠正”。

**控制平滑度：** 建议先对线速度与角速度分别按其允许范围归一化，再计算相邻时间步控制向量的平均变化。例如，使用相邻归一化控制向量的 L1 距离均值。这样可以避免线速度与角速度的物理量纲差异直接影响指标。

**碰撞率：** 当实际行驶距离为零时，应定义明确的边界处理规则，避免除零或产生不可比较的结果。

`ask_rate` 只反映策略发出求助请求的频率，不代表这些请求都正确，也不代表真实人类监督系统能够及时响应。后续应根据任务需要补充求助准确率、漏报率和人工响应延迟等指标。

### 实验对比建议

正式评测至少应比较：

- **BC：** 基于初始教师示范训练的行为克隆策略；
- **DAgger：** 在策略访问状态上进行数据聚合和迭代训练的策略；
- **消融实验：** 去除纠正 token、历史记忆或约束状态输入，比较其对纠正响应与任务成功率的影响；
- **参考教师：** 在相同环境条件下报告教师规划器的参考表现，但不得将其结果当作学习策略的性能。

各方法应使用相同的测试 episode、起终点、障碍配置和评测条件，并报告多随机种子的均值与离散程度。小规模 smoke 测试只用于检查流程是否工作，不足以支持算法优越性结论。

## 已知限制与后续扩展

- **语言表示：** 当前使用固定、版本化的 token 词表，不支持自由文本理解，也不依赖在线 LLM。
- **仿真环境：** 当前采用二维距离射线、简化运动学与栅格 A* 教师，尚未完整建模真实传感器噪声、复杂动力学、执行时延与通信异常。
- **人机交互：** 当前的教师查询和模拟纠正不能等同于真实人类实时接管，尚需独立的遥操作接口、接管状态机及控制权切换机制。
- **DAgger 实现：** 应明确 beta 混合、教师查询和数据采样的具体策略。若只在动作偏差超过阈值时查询教师，应称为选择性教师查询或 DAgger 风格变体，不应直接假设它等价于标准 DAgger。
- **约束与安全：** 当前环境约束不构成真实机器人上的形式化安全保证，也没有证明策略面对所有纠正组合时都能保持正确行为。
- **真实部署：** 尚未实现 sim-to-real、ROS 2、Habitat、Isaac Sim 或 ONNX 导出，也没有完整的真实机器人控制接入。
- **持续学习：** 当前数据聚合与迭代训练不等同于在线持续学习；尚未解决真实运行期间的模型更新、灾难性遗忘、数据筛选和回滚问题。

后续可以在环境/观测适配器边界接入 Habitat 或 Isaac Sim，在策略 I/O 边界增加 ROS 2 节点与 ONNX 导出。适配器应保持可选，并且不得将在线路径规划器引入学习策略的部署推理路径。

真实人类接管应作为独立的控制接口实现，并明确控制权授予、执行暂停、状态同步、接管解除与恢复自主执行的条件。恢复自主执行前，应重新确认目标有效性、环境状态可信度、约束一致性与执行条件，而不能仅因人工接管结束就自动恢复。

最终，希望通过这一架构建立清晰的技术边界：**教师用于监督学习，人类用于交互纠正，学习策略负责自主决策，执行层负责落实约束，评测体系负责区分各部分的实际贡献。**
